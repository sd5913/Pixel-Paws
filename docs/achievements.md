# Pixel Paws 成就系统设计

成就册记录猫咪的桌面捣蛋。第一局能拿到入门徽章，熟悉挥爪和走位后可以挑战连拍和速通，平时随手玩也会积累进度。成就奖励是徽章，不额外加分。

在试玩首页点击右下角的 **Achievements** 按钮查看徽章和解锁条件。

## 首版徽章

| 徽章 | 玩家看到的解锁条件 | 图标 |
| --- | --- | --- |
| 初次闯祸 | 让任意 1 个目标掉下桌 | 掉落的蓝杯 |
| 肉垫出击 | 单局内挥爪命中 4 个不同目标 | 挥出的猫爪 |
| 一爪双响 | 单局内完成两次一爪命中至少 2 件目标 | 两个猫爪 |
| 桌面清空 | 单局清空所有目标并获得 3 星 | 空桌与星星 |
| 闪电收桌 | 在 25 秒内让所有目标掉下桌 | 带闪电的计时器 |
| 桌面多米诺 | 单局达成 6 连击 | 依次倾倒的彩色笔记本 |
| 惯犯小猫 | 在结算的回合中累计推落 75 个目标 | 猫爪奖杯 |

更新后的关卡有八个计分目标，「桌面清空」需要推落 8/8 个目标并获得 3 星。直接掉下桌计一次，倾倒后仍留在桌上的物品不计。目标名单来自场景配置。速通阈值为 25 秒。

## 玩家会看到什么

1. **首页**。成就册每页显示一枚徽章、名称和条件，可左右滑动或使用箭头翻页。锁定徽章有深灰蒙版和锁图标。累计类显示如 `17 / 75` 的进度。可以在设置里重置成就。
2. **对局**。在本局暂存达成的成就，保留完整的计时、得分和操作区域。
3. **结算**。清空和超时都可以解锁当局满足的徽章。有新徽章时，结算面板下方显示横幅和徽章名称。

## 结算与存档

- **每局的成绩以现有计分系统为准。** 在清空或超时的正式结算时，用最终快照的 `fallenCount` 和 `targetCount` 判断掉落成就。现有快照已经包含触发结算的最后一个目标，同一目标的重复物理事件也已去重。速通用结算时的精确剩余毫秒判断，刚好用满 25 秒仍算达成，暂停时间不计入。界面向上取整的秒数只用于显示。
- **挥爪读取真实命中。** 使用 `deskPhysics.swat()` 每次返回的目标 ID，与当前目标名单取交集并去重。每局记录挥爪命中的不同目标数量，以及单次命中至少两件的次数。暂停、结算后及模拟计分模式的动作不参与。
- **每局只写一次。** 成功开局时创建临时记录。清空或超时后，一次更新累计推落数与新解锁徽章，并把结果交给结算页。点 Restart 或 Home 提前退出时丢弃该局记录。`?debugScoring=1` 可以看成就册，但不会写入正式进度。
- **首版存当前设备。** 用 `localStorage` 的 `pixel-paws.achievements` 保存版本号、累计推落数，以及以固定 ID 为键的首次解锁时间。首次启动从零开始。此前已经解锁的徽章保留原来的时间与解锁状态。预览网页和 Android 应用各有自己的存档。读取失败时允许正常试玩，写入失败时可在成就册里提示本次进度仅在当前会话可用。

## 实现与验收

先做成就规则和本地存档，再接入主游戏的开局、挥爪和结算，最后加首页入口与徽章卡片。现有 `createScoring()` 在同一次结算中先发布最终快照，再触发 `onEnd`。界面应在成就计算完成后更新结算页的徽章区域，确保最后一个杯子解锁的徽章能显示在本局。成就规则模块可独立接收结算摘要、挥爪记录和已有存档。

验收用四条路径覆盖首版行为。

1. 直接推落第一个杯子并等到超时，解锁「初次闯祸」，累计为 1。刷新后徽章仍在。只倾倒杯子的回合不增加掉落进度。
2. 验证挥空及重复目标的处理，再用四件不同目标和两次双目标挥爪验证徽章。
3. 推落最后一个杯子时检查总分和成就一起显示。用 25.000 秒与 25.001 秒的有效用时覆盖速通边界，并验证暂停不会消耗有效用时。
4. 用已累计 74 件的存档开局，分别测试 Restart、Home、模拟模式和正式超时。只有正式结算能把进度推进到 75。同一局重复通知仍只累加一次。
